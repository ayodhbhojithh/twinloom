# Accessibility

**URL:** /accessibility
**Last updated:** [[NEEDS: publication date]]

We want this website to be usable by as many people as reasonably possible, including people using keyboards, screen readers, magnification, voice input, or changed text and colour settings.

## Our target

Our design and development target is the Web Content Accessibility Guidelines **WCAG 2.2 Level AA**. It is also the standard we build client websites to, as one of the eleven things included in every site we build.

For a private business the legal position is not identical to the public-sector accessibility regulations. The Equality Act 2010 can still require reasonable adjustments in the provision of services. This statement uses WCAG as a practical technical target, not as a claim that one standard covers every legal duty.

## What should be possible

> [[NEEDS: keep only the statements confirmed by the test. Delete any that the test does not support.]]

You should be able to navigate the website using a keyboard; see a visible focus indicator; zoom and reflow the content without losing the main information; use headings and landmarks to move around; understand form labels, instructions and errors; avoid non-essential motion; use text alternatives for meaningful images; use every control without relying on colour alone; and complete the enquiry and scoping journeys with supported assistive technology.

## Note for the developer, not for publication

WCAG 2.2 adds nine success criteria over 2.1. These are the ones that commonly fail on a site like this one, and they should be tested before the conformance status above is filled in:

- **2.4.11 Focus not obscured, minimum.** A sticky header hiding the focused element.
- **2.4.13 Focus appearance.** Focus indicator size and contrast.
- **2.5.7 Dragging movements.** Any slider or drag interaction needs a single-pointer alternative. The colour ordering tool is the one to check.
- **2.5.8 Target size, minimum.** 24 by 24 CSS pixels. Footer links and social icons are the usual failures.
- **3.2.6 Consistent help.** Help mechanisms in the same relative order across pages.
- **3.3.7 Redundant entry.** Not asking for the same information twice within one process. The scoping journey already satisfies this: the send step shows the contact details back rather than asking a second time.
- **3.3.8 Accessible authentication, minimum.** No cognitive function test. Not applicable unless a login is added.
